# Classroom-Android

使用 Jetpack Compose 和 Material 3 Expressive 的 Android 客户端首版，配合 classroom-web 后端开发。

## 当前页面

- 首页：沿用 CRTicket 的静态产品图标及 Google Sans Rounded 标题，名称为 Classroom。未登录时显示登录图标；登录后显示真实账号名与服务器头像，无头像时圆形区域留空。
- 设置：二级页面，仅包含“后端地址”。点击弹窗编辑，保存到本机，重启后保留。取消不保存，留空保存可清除地址。
- 登录：账号、密码、密码可见切换、原生图形验证码及登录按钮；登录成功返回首页。已登录账号入口展示身份、姓名、学号和班级，并提供退出登录。

页面遵循系统深浅色与动态配色，支持边到边布局、滚动及输入法避让。界面字符串统一维护在 res/values/strings.xml。

## 后端地址

填写服务器根地址，例如 http://192.168.1.100:3001，包含 http 或 https 协议，不包含 /api、查询参数、片段或账号密码。API 路径由后续网络层统一追加。

保存地址时只校验格式；进入登录页后实际连接后端并读取验证码。真机访问开发机应填写同一网络内的局域网地址。classroom-web 默认监听 127.0.0.1，真机联调时需在后端配置 API_HOST=0.0.0.0，并允许对应端口通过防火墙。本应用支持局域网 HTTP 联调，正式部署建议使用 HTTPS；生产后端的 Secure Cookie 要求 HTTPS。

## 原生登录与会话

Android 使用 HttpURLConnection 和协程访问接口，没有 WebView。验证码由 AndroidSVG 渲染到原生 Bitmap，再交给 Compose 显示。请求路径：

- GET /api/captcha：保存验证码会话 Cookie，验证码一次性使用，失败后自动更新，可手动换一张。
- POST /api/android/auth/login：提交 username、password、code，由后端决定 android 会话类型。
- GET /api/auth/me：启动、返回首页和已有登录用户恢复前台时校验登录态。
- GET /api/profile：登录及恢复会话时读取当前用户资料；学生展示姓名、学号和班级，空班级显示“未分配”。
- POST /api/auth/logout：销毁本次会话，成功后清除本机 Cookie。

同账号一个 Web 和一个 Android 可同时在线，同端新登录替换旧登录；改密、停用、移除、密码重置会撤销全部会话。更新后需重启 classroom-web API，再安装新的 Android APK。

密码只留在登录页内存，不保存。Cookie 按后端根地址隔离，采用 Android Keystore AES/GCM 加密保存，并排除系统云备份与设备迁移；重启后通过 /auth/me 恢复用户，切换后端不会发送其他服务器的 Cookie。网络失败保留现有用户信息，收到有效 401 后回到未登录状态。请求禁止自动重定向，采用系统默认 TLS 校验。

## 头像上传与审核（2026-11-05）

在最新下载的项目上合并头像显示、账号页“修改头像”入口和 Compose 编辑页面，保留课程、学生登录限制及局域网权限等现有功能。

系统选图后验证 JPEG/PNG 格式、5 MiB 上限与可解码性，显示圆形预览；不裁剪或替换原文件。用户确认本人照片及检测/审核用途后，点击“提交”。本地检查不代替后端的人脸检测。

按组员更新后的 README 接入：

- POST /api/avatar-requests：multipart 的 file 字段，复用 Android 登录 Cookie；仅在收到 202 和有效 requestId 后显示提交成功。
- GET /api/requests：读取 items，过滤 kind=avatar_change，显示最新申请的 status 和 review_note；待审核或未知状态阻止重复提交，读取失败时禁用提交并提供刷新入口。
- GET /api/auth/me：刷新审核状态、返回首页或恢复前台时更新用户头像；审核通过前继续显示旧头像。图片接口沿用同源 Cookie，禁止将 Cookie 发送到外站。

网络异常不自动重发照片；提示用户刷新申请状态确认结果。拒绝后可重选照片再次提交。设备旋转或退出页面后不会自动上传，须重新确认同意。

以最新 README 为准，本功能只修改头像，不调用旧讨论稿中的 /face-avatar-requests，也不直接调用 CompreFace 或更改考勤人脸样本。CompreFace Key 仅保存在后端。自动检测无法保证排除全部动画、合成图片或确认本人身份，仍需管理员审核。

联调前提：部署包含上述接口的新版后端，配置 COMPREFACE_URL、独立的 COMPREFACE_DETECTION_API_KEY 及 pose 插件。客户端未新增文档未约定的同意字段或独立授权接口；若服务端需要记录授权，须由双方补充明确字段。

验收顺序：学生上传单人正脸 → 返回申请编号及待审核 → Web 管理员批准 → 安卓刷新状态并显示新头像；再测试拒绝并显示原因、多人/无人脸、超限、检测服务不可用、会话过期和重复提交。真实 CompreFace 与审核闭环需新版后端及真实服务联调，不能用本地格式验证或构建通过替代。

本轮验证：APK 与仪器测试 APK 构建成功；10 项 JVM 单元测试全部通过（含 multipart 二进制保真、5 MiB 边界、格式限制、头像 URL 与 Cookie 同源限制）；Lint 无错误、有 13 项警告。已使用 adb install -r 安装到连接的 Xiaomi 手机，保留应用数据。未运行会卸载应用的设备测试；新版后端仍由组员并行开发，尚未完成真实上传、人脸检测及管理员审核闭环联调。

## Android 17 局域网权限

目标 SDK 37 的应用在 Android 17 上访问局域网后端，需要声明并动态申请 `android.permission.ACCESS_LOCAL_NETWORK`。应用启动时通过系统授权对话框申请权限；未授权时提供“允许局域网访问”入口。Android 12 等旧版本直接进入应用。

## 学生专用登录与验证码输入（2026-11-04）

Android 仅允许学生登录。教师和管理员提交正确凭据及验证码时，后端返回 `403 ANDROID_STUDENT_ONLY`，不创建 Android 会话；客户端弹出 Material 3 对话框“无法登录”，提示使用学生账号。Web 登录不受影响。客户端恢复已有非学生会话时也会拒绝进入并退出该会话。

验证码字段保持明文，通过 Compose 输入连接设置 `TYPE_TEXT_FLAG_NO_SUGGESTIONS`、`TYPE_TEXT_VARIATION_VISIBLE_PASSWORD` 和 `IME_FLAG_NO_PERSONALIZED_LEARNING`，关闭自动纠正，要求输入法不提供联想、不进行个性化学习。该设置只作用于验证码字段。

本次仅操作 OPPO PDYM20。实测教师登录被拒绝并显示对话框，系统编辑器信息为 `inputType=0x80091`、`imeOptions=0x83000006`，包含禁止建议和禁止个性化学习标志。该机仅安装百度输入法，未实测 Gboard 界面或其内部存储。Android 构建、单元测试、Lint 及后端 Android 登录 7 项测试通过。
